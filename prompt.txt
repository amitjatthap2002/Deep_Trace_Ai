DeepTrace AI — Complete Build Prompt
PROJECT BUILD PROMPT: DeepTrace AI
====================================
(AI-Powered Digital Media Authenticity Verification SaaS Platform)
====================================================================
1. PROJECT OVERVIEW
====================================================================
Build "DeepTrace AI" — a full-stack, production-grade SaaS platform that
verifies the authenticity of digital media (images, videos, audio) using
multi-agent AI forensic analysis. The platform detects deepfakes,
AI-generated content, and manipulated media, and produces a final
Trust Score (0-100) with a detailed explainable report.
Target users: media organizations, cybersecurity firms, law enforcement,
digital forensic investigators, journalists, and fact-checking agencies.
Core value proposition: Upload any image/video/audio -> get a complete
forensic breakdown -> receive a Trust Score + AI-generated explainability
report (JSON + PDF) -> integrate via dashboard or REST API.

 gradient analysis, using YOLOv8 object boxes as anchor points to

4. LANGGRAPH MULTI-AGENT ARCHITECTURE
====================================================================
Implement this as a LangGraph StateGraph. Nodes:
START
 -> Upload Media Node (persist file, generate hash, store metadata row)
 -> Media Validation Node (type/size/corruption checks)
 -> Parallel branch (fan-out) into 4 agents:
 A) Metadata Agent
 - EXIF extraction (camera model, software used, timestamps)
 - GPS coordinate extraction & reverse-geocoding
 - File creation/modification metadata
 - SHA256 + perceptual hash generation
 - Flags: metadata stripped / inconsistent timestamps / editing
 software signatures (Photoshop, GIMP, FFmpeg re-encode markers)
 B) Deepfake Agent
 - Face detection (RetinaFace, MTCNN fallback) + face-swap /
 GAN-artifact classifier on detected face crops
 - AI-generated image detection (diffusion model artifact detection)
 - Video: frame-by-frame sampling + temporal consistency check
 - Audio: voice clone detection (spectrogram-based classifier)
 - Lip-sync mismatch detection for video+audio pairs
 - Output: probability score (fake/real) + confidence + heatmap
 C) Forensic Agent
 - Error Level Analysis (ELA)
 - JPEG double-compression / quantization table analysis
 - Copy-move forgery detection (keypoint matching, e.g. ORB/SIFT)
 - Noise pattern / camera sensor fingerprint (PRNU-style) analysis
 - Shadow consistency check (light direction vs shadow geometry,
 using YOLOv8-detected object boxes as reference anchors)
 - Lighting consistency check across objects/faces in frame
 - Object consistency check: run YOLOv8 to detect all objects,
 then flag scale mismatches, duplicated/cloned objects, floating
 or misaligned objects, and boundary/edge anomalies at object
 contours
 D) Context / Fact-Check Agent
 - OCR text extraction from media
 - Reverse image search across the web
 - Cross-reference extracted text/claims against fact-check sources
 - Return matched source URLs, first-seen dates, and context flags
 -> Evidence Aggregation Node (merge all 4 agent outputs into one
 structured evidence object)
 -> Trust Score Calculator Node
 - Weighted scoring model combining:
 metadata_integrity_score (15%)
 deepfake_authenticity_score (35%)
 forensic_consistency_score (30%)
 context_verification_score (20%)
 - Output: trust_score (0-100), risk_level (Low/Medium/High/Critical)
 -> LLM Report Generator Node
 - Feed aggregated evidence into an LLM prompt
 - Generate a human-readable explainability report: summary,
 key red flags, confidence reasoning, recommendation
 -> END -> persist FINAL_REPORT row, generate PDF, return JSON via API
Use conditional edges to skip agents not relevant to the media type
(e.g., skip Voice Clone Detection for pure images; skip Lip-Sync for
audio-only files).

6. DATABASE SCHEMA (PostgreSQL)
====================================================================
Table: users
 - user_id UUID PK
 - name VARCHAR
 - email VARCHAR UNIQUE
 - password_hash VARCHAR
 - role VARCHAR (admin/analyst/client)
 - created_at TIMESTAMP
Table: media_file
 - media_id UUID PK
 - user_id UUID FK -> users
 - filename VARCHAR
 - media_type VARCHAR (image/video/audio/document)
 - storage_path VARCHAR
 - sha256_hash VARCHAR
 - file_size_bytes BIGINT
 - upload_time TIMESTAMP
 - status VARCHAR (pending/processing/completed/failed)
Table: metadata
 - metadata_id UUID PK
 - media_id UUID FK -> media_file
 - exif_data JSONB
 - gps_lat FLOAT
 - gps_lng FLOAT
 - capture_timestamp TIMESTAMP
 - camera_make VARCHAR
 - camera_model VARCHAR
 - software_used VARCHAR
 - flags JSONB
Table: deepfake_result
 - result_id UUID PK
 - media_id UUID FK -> media_file
 - probability_fake FLOAT
 - verdict VARCHAR (real/fake/uncertain)
 - confidence FLOAT
 - heatmap_path VARCHAR
 - model_version VARCHAR
Table: forensic_result
 - forensic_id UUID PK
 - media_id UUID FK -> media_file
 - ela_score FLOAT
 - shadow_score FLOAT
 - lighting_score FLOAT
 - compression_score FLOAT
 - copy_move_detected BOOLEAN
 - camera_fingerprint_match BOOLEAN
 - details JSONB
Table: fact_check_result
 - fact_id UUID PK
 - media_id UUID FK -> media_file
 - reverse_search_matches JSONB
 - ocr_text TEXT
 - verified_sources JSONB
 - first_seen_date TIMESTAMP
 - context_flags JSONB
Table: final_report
 - report_id UUID PK
 - media_id UUID FK -> media_file
 - trust_score FLOAT
 - risk_level VARCHAR
 - ai_summary TEXT
 - pdf_path VARCHAR
 - created_at TIMESTAMP
Relationships: users 1-N media_file; media_file 1-1 metadata;
media_file 1-1 deepfake_result; media_file 1-1 forensic_result;
media_file 1-1 fact_check_result; media_file 1-1 final_report.

8. TRUST SCORE CALCULATION LOGIC
====================================================================
trust_score = round(
 0.15 * metadata_integrity_score +
 0.35 * (100 - deepfake_probability_fake) +
 0.30 * forensic_consistency_score +
 0.20 * context_verification_score
)
risk_level mapping:
 80-100 -> Low Risk (Likely Authentic)
 60-79 -> Medium Risk (Some Inconsistencies)
 35-59 -> High Risk (Likely Manipulated)
 0-34 -> Critical Risk (Strong Evidence of Manipulation)
Each sub-score must be independently explainable in the final report
(list which specific checks contributed positively/negatively).

11. NON-FUNCTIONAL REQUIREMENTS
====================================================================
- All uploaded media must be virus/malware scanned before processing
- File size limit: configurable (default 200MB video / 25MB image)
- All agent processing must be async and non-blocking (Celery workers)
- System must degrade gracefully: if one agent fails, others still
 complete and the report notes the missing analysis
- Full audit log of every analysis request per user
- Clear separation of concerns: each agent is an independently testable
 Python module/service, not tightly coupled to the LangGraph node
